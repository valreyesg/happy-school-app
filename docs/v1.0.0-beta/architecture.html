01 Visión General del Sistema

Happy School App es un sistema de gestión para kinder (jardín de niños) con 4 portales distintos según rol:

PortalPlataformaRolFunción principal
DirectoraWebdirectoraAdministración completa: alumnos, pagos, personal, config
MaestraWeb + Mobilemaestra_titular / maestra_especial / maestra_puertaFiltro entrada/salida, bitácora diaria, asistencia
PadreWeb + MobilepadreVer bitácora hijo, pagos, QR de entrada, calendario
AdministrativoWebadministrativoFinanzas y reportes

Flujo diario típico

  1. 1Padre llega con hijo → muestra QR en app mobile
  2. 2Maestra en puerta escanea QR (mobile) o busca alumno (web)
  3. 3Se registra entrada con checklist de salud/higiene/materiales
  4. 4Durante el día: maestra llena bitácora (alimentación, conducta, salud, pañal)
  5. 5A la salida: maestra registra salida y quién recoge al alumno
  6. 6Padre ve todo en tiempo real desde su app mobile o web

04 Backend — Arquitectura

Middleware Stack — orden en app.js

#MiddlewareFunción
1helmet()Headers de seguridad, CORS policy cross-origin
2compression()GZIP en respuestas
3morgan()Logging HTTP (dev o combined según NODE_ENV)
4cors()Orígenes: WEB_URL, MOBILE_URL, localhost:5173, localhost:3001, exp://localhost:8081
5express-rate-limit()300 requests / 15 minutos
6express.json(10mb)Parse JSON
7Cache-Controlno-store en /api/ — evita HTTP 304 (bug histórico #12)
8/uploads → staticArchivos locales en desarrollo
9/api/* → routesTodas las rutas definidas en routes/index.js
10GET /health{"status":"ok","app":"Happy School API","version":"1.0.0"}
11errorHandlerÚltimo — captura excepciones, formatea JSON error

authenticate() — middleware/auth.js

Lee Authorization: Bearer <token>, verifica con JWT_SECRET, hace query a usuarios WHERE activo=true, pone req.user.

Códigos de error: TOKEN_EXPIRED (para refresh automático) vs 401 genérico para otros casos.

authorize(...roles) — middleware/auth.js

Directora siempre pasa sin importar los roles requeridos. Para otros roles: consulta roles_usuario y verifica contra rol_principal + roles adicionales.

Pool de BD — config/database.js

Max 20 conexiones · Idle timeout 30s · Timezone: America/Mexico_City en cada cliente · Logs queries >100ms en dev.

08 Servicios Externos

Cloudinary (services/cloudinaryService.js)

Upload de fotos de alumnos, tutores, QR codes, bitácora, actividades, documentos.

Flag: CLOUDINARY_ENABLED=false → mock en dev (retorna data URL base64 — imagen visible sin cuenta Cloudinary real).

Carpetas: happyschool/qr/, happyschool/bitacora/, happyschool/actividades-alumno/, happyschool/tareas/, happyschool/visitantes/

WhatsApp Twilio (services/whatsappService.js)

Usa plantillas de la tabla plantillas_whatsapp (editables por directora). Verifica whatsapp_activo en config antes de enviar. Loguea cada envío en log_whatsapp.

Expo Push (services/pushService.js)

Envía a exp.host/--/api/v2/push/send. Token como ExponentPushToken[xxx] en usuarios.fcm_token.

Push funciona 100% en APK y development build. En Expo Go: registro OK pero entrega limitada (limitación de Expo, no es un bug del código).

URL base del API

// web/src/services/api.js

Auth Store (Zustand)

Persistencia en localStorage, key: happy-school-auth. Estado: { token, refreshToken, usuario }. Axios lee el token en cada request via interceptor de request.

Refresh automático de token

Al recibir 401 TOKEN_EXPIRED: encola requests pendientes → POST /auth/refresh → actualiza tokens → reintenta. Si el refresh falla: logout forzado + redirect a /login.

Flujo de login

POST /api/auth/login { email, password }
  → Backend verifica bcrypt hash
  → Retorna { accessToken (15min), refreshToken (7días), usuario }
  → Web: guarda en localStorage  |  Mobile: guarda en SecureStore
  → Axios agrega Bearer en cada request

Refresh token

Request → 401 TOKEN_EXPIRED
  → POST /auth/refresh { refreshToken }
  → Backend rota tokens (invalida viejo, emite nuevos)
  → Actualiza storage + reintenta request original
  → Si falla: logout forzado → /login

15 Reglas de Negocio Críticas

Retardo (Late Arrival)

  • Si hora_entrada > hora_fin_filtro (de config) → es_retardo=true
  • numero_retardo_mes se acumula por mes calendario
  • Al llegar a max_retardos_mes (default 3): puede_entrar=false al día siguiente
  • Dashboard padre: ⚠️ 1-2 retardos (aviso), 🚫 3+ (bloqueado)
  • WA plantilla retardo se envía automáticamente al registrar

Cadena de Hermanos (Sibling Chain)

  • Al registrar entrada/salida de alumno A → backend retorna hermanos via GET /alumnos/:id/hermanos
  • Hermanos = mismo familia_id UUID o mismo tutor principal (es_tutor_principal=true)
  • UI ofrece registrar hermanos en secuencia sin re-escanear QR
  • Pre-llena "quién recoge" del hermano anterior para ahorra tiempo

QR Temporal

  • 1 QR activo por alumno por día (fecha_vigencia = CURRENT_DATE México)
  • Padre ingresa nombre de quien va a recoger
  • Format QR: HAPPYSCHOOL:TEMP:<token> (distinto del permanente HAPPYSCHOOL:ALUMNO:<uuid>)
  • Maestra ve banner amarillo al escanear: "PASE TEMPORAL — Verificar identidad"
  • Se invalida a medianoche hora México (no UTC) — ver sección 16

Extensión de Horario

  • Tabla config_horario_alumno: tiene_extension, hora_salida_extension, genera_cargos
  • Si genera_cargos=true: cargo mensual generado automáticamente cada día 1
  • Job sinRecogerJob respeta extensión: no alerta hasta hora_salida_extension + gracia
  • Precios diferenciados por nivel en tabla precios_nivel

Comida Semanal

  • Padre confirma antes del domingo de cada semana
  • Lunes 7:00 AM: recordatorio WA si no pagó
  • Lunes 8:31 AM: cancela automático si no llegó pago
  • estado !== 'cancelado' controla si se muestra sección comida en filtro entrada
  • 3 estados visuales: pendiente (rojo), pagado (verde), cancelado (gris)

16 Manejo de Fechas y Zona Horaria

🚨 Esta sección causó 20+ bugs durante el desarrollo. Leer antes de tocar cualquier comparación de fechas. La app opera en America/Mexico_City (UTC-6).

Reglas — qué usar y qué NO usar

Caso❌ Incorrecto✅ Correcto
Fecha de hoy en frontendnew Date().toISOString().slice(0,10)new Date().toLocaleDateString('en-CA', { timeZone: 'America/Mexico_City' })
Fecha de hoy en SQLNOW()::dateCURRENT_DATE
Parsear fecha del APInew Date(apiDate)new Date(apiDate.substring(0,10))
Comparar fechasDirecto con ISO completoExtraer con .substring(0,10) primero

Por qué falla toISOString()

toISOString() devuelve hora UTC. A las 7 PM hora México (UTC-6) ya son las 00:00 AM del día siguiente en UTC. Esto rompió QR temporal, cumpleaños, filtros de asistencia y todas las queries que comparaban con "hoy".

El API siempre devuelve ISO completo

// El API retorna: "2022-04-17T05:00:00.000Z"
// SIEMPRE hacer:
const soloFecha = apiDate.substring(0, 10)  // "2022-04-17"
const date = new Date(soloFecha)            // fecha correcta
